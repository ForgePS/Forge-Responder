# FORGE Field (offline field app)

A phone-first app for Fire/EMS crews at `<department>.forgeresponder.com/field`
(or `/<department>/field` on the shared domain). It opens and saves records with
no connection and sends them automatically when the device is back online.
Department administrators customize it in the RMS under **System Admin →
FORGE Field (field app)**. The desktop RMS itself is unchanged.

Screenshots: [docs/field-app](field-app/).

## What crews can do

| Workflow | Writes (same shapes as the desktop pages) | Shown when |
|---|---|---|
| Truck check | `fleetChecks` + `completeFleetCheck` (meter readings, defects for failed items, asset readiness, OOS/restrict decision, audit) | Apparatus module + conduct-checks permission |
| EMS unit check-off | `fieldCheckoffs` (counts, short / missing / expired / expiring items, restock list) | Lists exist for EMS units |
| Supply closet check-off | `fieldCheckoffs` (same, for station supply closets) | Lists exist for supply closets |
| Hydrants | inspections (`hydrantInspections`, item photos, repair flags), flow tests (`hydrantFlowTests`, NFPA override, hydrant info), hydrant info edits, `dailyActivity`, hydrant summary on `hydrants`; crew shift session, district filter, counts, map | Hydrants module |
| Hydrant damage | `hydrantDamageReports` via `createHydrantDamageReport` (ownership review, audit), photos | Hydrants module + damage draft permission |
| Hose testing | `hoseTests` (one record per hose) | Hose Testing or Hydrants module + Hose Testing page access |
| Damage form | work order in the work-orders list, `damageForms`, internal email to battalion chiefs, audit log, photos | Maintenance or Hydrants module + submit-maintenance permission |
| Daily log | one item in the daily-logs list (auto-lock time, lock respected) | Daily Log module + view/edit permission |
| Incident report | NERIS draft in the NERIS list (type, address, times, units, crew, patients, narrative); finished in the RMS | NERIS module + edit permission |
| Inspections | inspections assigned to the inspector: answers (`saveInspectionDraft` / `completeInspection`), violations (`createViolation`), photos | Inspections module + edit/conduct permission |
| Pre-fire plans | view plans (published revision) and their files offline; **editors** create plans (`createPreplan`, draft) and edit them (draft revision via `startPreplanRevision` → approval in the RMS) or plan-library records (`preFirePlans`); **everyone else** sends updates for review (`fieldPlanUpdates`) | Pre-plan view permission or Hydrants access; editors = "Can create & edit" roles, or pre-plan edit permissions |

Every write still goes through Firestore rules, so a stale permission snapshot on
a device can't grant anything on the server.

## Customizing (System Admin → FORGE Field)

- **General**: app name and logo shown in the field app's top bar.
- **Workflows**: switch each workflow on or off and choose which roles get it
  (people still need the matching permission). Pre-fire plans also have
  "Can create & edit" roles.
- **Form fields**: for each form, set fields to Show / Hide / Required for the
  whole department, and override per role (with several roles the most visible
  setting wins: Required, then Show, then Hide). Fields a record can't be saved
  without are always required and aren't listed. Truck check items come from
  Fleet → Configuration Studio, inspection items from inspection templates.
- **Check-off lists**: EMS unit and supply closet lists: items, category, par,
  unit, expiration tracking with warning days, required, order.
- **Check-off results**: recent counts with the restock list; "Mark restocked".
- **Plan updates**: updates crews sent from pre-fire plans; review, then mark
  reviewed or dismiss.

Phones pick up settings on their next data update (on open with signal, every 20
minutes, after a sync, or Update on the home screen). Settings, check-off lists and
restock marks are admin-only in Firestore rules (Fire Chief, IT Admin, Department
Admin, creators).

## How offline works

- **App files**: a service worker (`dist/sw.js`, generated by
  `vite-plugins/fieldServiceWorker.js`) is registered for the field app's own
  address only (`/field`, `/<department>/field`), so the desktop RMS never goes
  through it. It stores the app entry, the field app's code and CSS on the first
  visit. Pages are network-first with the stored shell as fallback; hashed
  `/assets/*` are cache-first. Map tiles and plan photos viewed online are kept for
  offline use. Firestore, Auth and other sites are never intercepted.
- **Sign-in**: Firebase keeps the sign-in on the device (two-factor accounts enter
  their authenticator code). Each online start saves an access snapshot
  (department, roles, permissions, modules) in IndexedDB, so the app can open
  offline. One connected start per device is required.
- **Reference data**: FORGE Field settings, apparatus, published checklists,
  check-off lists, hydrants, today's hydrant activity, personnel, recent daily
  logs, NERIS drafts, assigned inspections and the violation code list, and
  pre-fire plans are downloaded to IndexedDB when online. If one part fails the
  previous copy is kept.
- **Records**: everything is saved to IndexedDB first (`src/field/fieldRecords.js`).
  New forms autosave as drafts while typing; "Pick up where you left off" on Home.
- **Plan files**: "Save offline" on a plan stores its files on the phone. PDFs need
  the storage bucket to allow browser downloads (CORS), one-time setup:

  ```bash
  gsutil cors set storage.cors.json gs://<your-storage-bucket>
  ```

  Without it, photos still show offline once viewed; PDFs open only with signal.

## Sync and conflict rules (`src/field/fieldSync.js`, `fieldSyncHandlers.js`)

- Records send oldest first when the device is online (also on app focus and
  every 30 s). Ids are fixed on the device, so a retry overwrites instead of
  duplicating. Multi-step records (truck check, damage form, inspection, new plan)
  remember finished steps and resume.
- Connection problems: the record stays "Saved on device" and retries with
  backoff (15 s doubling to 10 min). If the phone says it's online but the server
  can't be reached, the status shows "No signal".
- The server refuses a record (permissions, plan, locked log/report, inspection
  completed in the RMS): the record is marked **Needs attention**, kept on the
  device, and can be edited and sent again, downloaded as a JSON copy, or
  discarded (with a confirmation).
- Edits to records that already exist on the server (daily logs, NERIS drafts,
  inspection answers, pre-fire plans, hydrant info) use a three-way merge per
  field: fields only the crew changed are applied; fields changed on the server
  too are shown side by side to keep mine / theirs / both. Hydrant summaries are
  only updated if the field check isn't older than the server's. Late truck checks
  don't overwrite a newer check's readiness.
- Status pill (always visible): Offline · N saved on device / Syncing N… /
  All synced / N need attention.

## Install and updates

- Android/Chrome: "Add FORGE Field to home screen" on the Device tab; iPhone:
  Share → Add to Home Screen (instructions shown in the app).
- A new deploy installs in the background; a banner offers "Update" (disabled
  while a record is being sent). Records are in IndexedDB, so updating loses nothing.
- Hosting headers: `sw.js` is never cached; `field.webmanifest` is revalidated.

## Changes outside `src/field/`

- `src/main.jsx`: lazy `/field` route (the desktop bundle doesn't load field code).
- `src/components/FieldAppSettingsPanel.jsx` (+ `.css`), mounted in
  `src/pages/AdminControlCenterPage.jsx`: the admin settings page.
- `firestore.rules`: `settings/fieldApp` admin-only; new `fieldCheckoffLists`,
  `fieldCheckoffs`, `fieldPlanUpdates` rules (tests in
  `tests/rules/firestore.rules.test.mjs`). **Rules need deploying** with the app.
- `src/lib/gatewayRouting.js`: `field` is a reserved path; the department URL sync
  leaves `/field` alone.
- `src/lib/tenantListStore.js`: `readTenantListItem` / `upsertTenantListItem`.
- `src/lib/fleet/fleetCheckService.js`: optional `completedAt`; late checks don't
  overwrite a newer check's readiness.
- `src/lib/hydrantDamage/damageReportService.js`, `src/lib/inspections/violationService.js`:
  optional fixed `id` so retried syncs can't duplicate.
- `index.html`: manifest/icon links on `/field`; `firebase.json`: headers;
  `vite.config.js`: service worker build step; `public/`: manifest, icons,
  fictional demo hydrants for the demo department; `storage.cors.json`.

## Testing

- `npm run test:unit` includes `tests/unit/fieldOffline.test.mjs` and
  `tests/unit/fieldSettings.test.mjs`; `npm run test:rules` covers the new rules.
- Airplane-mode end-to-end on the production build (headless Chrome, page and
  service worker forced offline; writes test records to the demo department):

  ```bash
  npm run build
  npx vite preview --port 4180
  npm run test:field-offline -- http://localhost:4180
  node scripts/field-e2e/field-v2.mjs http://localhost:4180
  ```

  `field-v2.mjs` needs an EMS check-off list for "Medic 1" in the demo department;
  it sets two field rules, checks them, and resets them at the end.

## Not in this version

- Photos on truck-check failures; signatures on inspections (collected in the RMS).
- New inspections are created in the RMS; the field app conducts assigned ones.
- Accounts that must use two-factor login need a connection to sign in the first time.
